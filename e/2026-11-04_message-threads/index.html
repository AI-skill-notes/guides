Claude API 메시지 스레드: 긴 대화는 새 메시지만 보내요 (공식 글 정리)

  • 영상(AI스킬노트 쇼츠, 11월 4일 아침 7시 공개): 공개 뒤 이 줄에 주소를 붙여요.
  • 출처: Anthropic 'Make long-running agents faster with message threads'(claude.com, 2026년 11월 2일) https://claude.com/resources/articles/message-threads
  • 정리한 날: 2026-11-03. 아래 내용은 공식 글 문장을 우리 말로 옮긴 거예요. 광고·협찬 아님.

무엇이 바뀌었나요

  • 메시지 스레드(message threads)가 Claude Platform에서 공개 베타로 나왔어요.
  • 지금까지 에이전트는 요청할 때마다 앞서 나눈 메시지와 도구 결과를 전부 다시 보냈어요. 코딩 에이전트는 한 세션에 요청이 수백 번이 될 수도 있어서, 대화가 길수록 Claude가 답을 시작하기까지 시간이 더 걸렸어요.
  • 메시지 스레드를 쓰면 첫 요청에만 대화 전체를 보내 스레드를 시작하고, 그다음 요청부터는 새 메시지와 앞 답의 ID만 보내요.

얼마나 빨라지나요 (공식 글 숫자)

  • 대부분의 Claude Code 사용자에게는 이미 기본으로 켜져 있어요.
  • 50만~100만 토큰 요청에서 첫 토큰까지 걸리는 시간(TTFT) 중간값이 약 35% 줄었다고 해요.

알아 둘 것

  • 스레드는 마지막 요청 뒤 5분이 지나면 끝나요. 그 뒤에는 클라이언트가 대화 전체를 다시 보내 새 스레드를 시작해요.
  • 요청 사이에는 스레드를 메모리에 두는데, 암호화돼 있고 디스크에는 쓰지 않는다고 해요.
  • 요청 크기는 작아지지만 Claude는 매번 대화 전체를 읽어요. 그래서 토큰 사용량은 그대로예요. 요금과 사용 한도도 기존과 같아요.
  • 쓸 수 있는 곳: Claude Platform, Claude Platform on AWS, Claude in Microsoft Foundry, Google Cloud의 Claude 모델(Anthropic 관리).

체크리스트: 직접 API를 쓴다면

  • [ ] 대화가 길고 응답 속도가 중요한 작업(오래 도는 코딩 에이전트, 화면을 찍어 보내는 컴퓨터 사용 에이전트, 문서·이미지가 많은 작업)인지 확인해요.
  • [ ] Messages API 요청에 thread 값을 넣는 방법은 공식 문서에서 확인해요(글의 'documentation' 링크).
  • [ ] 5분 넘게 쉬면 다음 요청은 대화 전체를 다시 보내요. 이 경우도 처리하도록 만들어 둬요.
  • [ ] 토큰 비용을 줄이려는 거라면 메시지 스레드가 아니라 다른 방법(예: 프롬프트 캐싱)을 살펴봐요.
